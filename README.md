# TRMNL Creator — Calendar Studio

A Phoenix LiveView BYOS dashboard for one TRMNL OG. Combine read-only Google calendars from several accounts with family plans, meals, chores, countdowns and notes. Manage content independently, arrange blocks on a 20×12 grid, preview the 800×480 monochrome result, and explicitly publish the layout.

Defaults are Polish, Europe/Warsaw, Monday-first weeks and 24-hour time. Calendar blocks include grouped agendas, week columns/rows and a month overview. V1 deliberately excludes playlists, multiple devices, calendar editing, custom HTML, public registration and `trmnlp` compatibility.

## Features

- Connect multiple Google accounts and choose which calendars appear on each block.
- Manage todos, meals, household chores, countdowns and family notes.
- Drag and resize blocks, save a draft, and preview the screen before publishing.
- Serve the last successful image to your TRMNL while synchronization or rendering recovers from a failure.
- Run Phoenix LiveView, PostgreSQL and the Chromium renderer together with Docker Compose.

## Deploy on an amd64 home server

For TrueNAS Apps using GHCR images, follow the [TrueNAS installation and update guide](docs/DEPLOY_TRUENAS.md). It uses a dedicated database dataset and runs migrations automatically on startup.

Requirements: Docker Engine with Compose v2, approximately 2 GB available RAM plus image/build storage, a hostname or LAN IP reachable by your TRMNL. All services explicitly target `linux/amd64`.

```sh
python3 scripts/generate_env.py
# Edit .env: set PUBLIC_URL to http://YOUR_SERVER_IP:4000 (or your HTTPS URL).
python3 scripts/preflight.py .env
docker compose up --build -d --wait
docker compose ps
```

The generator creates fresh secrets without printing them and refuses to overwrite an existing `.env`. Retrieve `ADMIN_PASSWORD` from that file to log in. Never commit it. Database passwords generated by the script are URL-safe. `TOKEN_ENCRYPTION_KEY` must be base64 encoding of exactly 32 random bytes; keep this key with your database backup. Changing it makes stored Google credentials unreadable. `SECRET_KEY_BASE` signs admin sessions and temporary image links. Changing the admin password invalidates existing admin sessions on their next authentication check.

Only the app port is published. PostgreSQL and the authenticated renderer are internal services. `BIND_ADDRESS` defaults to `0.0.0.0`; restrict it if using a reverse proxy. The dashboard and device transport use the scheme in `PUBLIC_URL`. Use HTTPS or a trusted private LAN/VPN; do not expose plain HTTP credentials to the internet. An HTTPS reverse proxy must forward WebSocket upgrades to `/live/websocket`. Image URLs use `PUBLIC_URL`, never the incoming Host header.

The app runs database migrations before starting. `/health` verifies database access; Compose separately checks Chromium health. Containers run the app and renderer as unprivileged users. `ERL_FLAGS=+JMsingle true` also permits amd64 validation through Rosetta on an Apple Silicon host.

## Connect Google Calendar accounts

For the local app on port 4010, follow [the Polish setup guide](docs/GOOGLE_SETUP.md). `python3 scripts/start_dev.py` loads `.tmp/google-oauth.json` when present and starts the app on 4010 with a matching callback. Without OAuth credentials the dashboard shows setup instructions instead of redirecting to Google.


1. Create a Google Cloud project and enable **Google Calendar API**.
2. Configure the OAuth consent screen. For a personal external app in Testing, add every Google account you will connect as a test user. Google may expire refresh tokens for external apps in Testing; reconnect if access expires, or complete Google's production requirements.
3. Create an OAuth client of type **Web application**. Add the exact authorized redirect URI `http://localhost:4000/oauth/callback`.
4. Set `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` and `GOOGLE_REDIRECT_URI` in `.env`. Restart the app with `docker compose up -d --force-recreate app`.
5. From your laptop, establish a tunnel:

   ```sh
   ssh -N -L 4000:127.0.0.1:4000 YOUR_USER@YOUR_SERVER
   ```

6. Open **http://localhost:4000** in that laptop's browser and log in there. Click **+ Konto Google**, consent to calendar read access, then select the calendars to synchronize. Start the flow on localhost so the callback receives the same session cookie. Repeat for the second account. If laptop port 4000 is occupied, use another local port consistently in the tunnel, Google redirect URI and `GOOGLE_BROWSER_ORIGIN`.

Only `https://www.googleapis.com/auth/calendar.readonly` is requested. OAuth state expires after ten minutes and is single-use. Access and refresh tokens are encrypted with AES-256-GCM before storage. Reconnecting an existing account replaces its authorization without losing the layout or selected calendars. Raw OAuth responses, arbitrary firmware log strings and submitted form values are not logged.

Every five minutes Oban fetches all pages of the calendar list and selected event calendars. It asks Google to expand recurring events (`singleEvents=true`) and include cancellations, then removes cancelled instances. Each account snapshot is replaced only after all selected calendars/pages succeed. The rolling window spans seven days back and 35 days ahead. Date-only all-day events use exclusive end dates; timed events are converted to Warsaw time, including DST. A sync failure retains the previous snapshot and records recovery instructions on the dashboard. **Synchronizuj teraz / ponów** enqueues an immediate retry.

Primary sources: [Google web-server OAuth](https://developers.google.com/identity/protocols/oauth2/web-server), [Google event listing](https://developers.google.com/calendar/api/v3/reference/events/list), [TRMNL firmware API](https://github.com/usetrmnl/trmnl-firmware#web-server-endpoints).

## Manage family content

The dashboard separates **Treść rodzinna** (content), **Układ ekranu** (layout), and **Kalendarze i urządzenie** (connections, pairing and diagnostics).

Manage each module in **Treść rodzinna** without opening the layout editor:

| Module | Content controls |
| --- | --- |
| Lista zadań | An undated todo list with person, details, complete and undo. The screen shows the first three unfinished tasks in creation order; completing one brings in the next. |
| Plan posiłków | Meals on any date, optional serving time, cook and notes. |
| Obowiązki domowe | Undated or dated chores, responsible person, priority, daily/weekly repetition, complete and undo. |
| Odliczanie | Upcoming dates and annual anniversaries, with days remaining. |
| Wiadomości rodzinne | Multiple notes, optional author, priority and inclusive display-from/display-until dates. |

Entries can be added, edited and removed independently. Saved changes queue a refresh of the **published layout**, without publishing draft layout edits. The TRMNL downloads the result on its next poll. Content remains saved even if rendering fails; the last successful image remains active while the refresh job retries. Modules can have several blocks sharing the same content, and removing a block does not delete its entries.

Dates follow Europe/Warsaw. Completed one-off chores disappear from the screen but remain manageable in the dashboard. Completing a recurring chore advances its next due date; missed cycles collapse to the latest outstanding occurrence. Yearly February 29 anniversaries fall on February 28 in non-leap years. Expired notes and past one-off countdowns remain in the dashboard but are omitted from the display. Scheduled refreshes also update date-sensitive content when no Google account is connected.

## Edit, preview and publish

- Open **Układ ekranu** and add a date/time, agenda, week, month, static text or family module block. Drag it to move; drag its bottom-right handle to resize. The inspector also provides numeric geometry controls for keyboard use. Switching tabs preserves the working layout.
- Choose calendars separately for each block, a title, text size and agenda horizon (1–30 days). An empty calendar selection intentionally shows no events. Week blocks need at least 14 columns and three rows.
- Click **Zastosuj** to apply inspector edits, then **Zapisz szkic** to persist the draft. Blocks may not overlap or leave the 20×12 grid. Concurrent draft edits are rejected using revision checks.
- **Podgląd** renders the current working layout, without publishing it. **Publikuj na TRMNL** saves and publishes that draft. The previous publication remains active until the new render succeeds.

Family blocks have the same geometry, title and font controls. Meals and reminders also have a 1–30 day horizon; overdue and undated reminders remain visible. Edit their entries in **Treść rodzinna**, then use Preview to check how much fits. Google calendar selection applies to agenda, week and month blocks. Choose classic, minimal or contrast headers, compact/comfortable spacing, grouped agenda days or week rows. The month overview shows event counts; older days outside the synchronization window show a dash.

Preview and publication both generate escaped HTML internally and pass it to the same Chromium/Playwright → ImageMagick pipeline. It blocks external browser requests and scripts, uses DejaVu Sans in Docker, and produces a one-bit, 800×480 grayscale PNG. Text overflow is marked **Więcej ↓**; partially visible event rows are hidden. Inspect the preview when changing a block's size or content.

PostgreSQL stores one draft, its revision, one published configuration, the active image and its hash. Rendering happens before the publication transaction commits. A failed render leaves both the previous layout and image intact. Scheduled calendar refreshes render the **published** configuration, including the current date, while leaving draft edits untouched. Sync and render diagnostics are independent, so cached data can still be displayed when Google is unavailable.

## Pair the TRMNL OG

1. Enter the OG's MAC address in the dashboard and click **Otwórz parowanie**. This opens a ten-minute, one-device pairing window and invalidates any old device token.
2. Point the device's BYOS API server at `PUBLIC_URL` through its Wi-Fi configuration portal. Trigger setup within that window.
3. The device exchanges its `ID` header for an API key. Pairing closes immediately after successful setup. If the response was lost, reopen pairing in the dashboard and retry.

Contracts:

| Endpoint | Authentication | Behavior |
| --- | --- | --- |
| `GET /api/setup` | Approved MAC in `ID`, during pairing; or existing `Access-Token` | API key, friendly ID and a signed BMP setup image |
| `GET /api/display` | `ID` + `Access-Token` | `status: 0`, signed image URL, image hash filename, `refresh_rate: 240` with a published clock, otherwise `900` |
| `GET /api/image?token=…` | Signed read-only URL, valid 24 hours | Current successful PNG, or setup PNG before first publication |
| `GET /api/setup-image.bmp?token=…` | Signed read-only URL | Uncompressed monochrome BMP for OG onboarding |
| `POST /api/log` | `ID` + `Access-Token` | Records safe issue categories and numeric telemetry, returns `status: 200` |

Device tokens are stored only as SHA-256 hashes. Failed credentials return HTTP 401. Image links are temporary bearer capabilities and must be treated as private. Numeric `Battery-Voltage` and `RSSI` headers update diagnostics; last contact updates on display/log requests. Logs classify Wi-Fi, HTTP, image, timeout and memory issues without storing raw messages, which may contain credentials. Firmware must support PNG display downloads; onboarding uses BMP for compatibility with older OG setup code. Physical firmware behavior still requires a hardware check.

## Operations and recovery

```sh
docker compose ps
docker compose logs --tail=100 app renderer
docker compose restart renderer
```

For a render error, restore the renderer, then click **Publikuj** to retry the draft or **Synchronizuj teraz / ponów** to refresh the existing publication. For Google errors, check connectivity and OAuth credentials, reconnect the account if needed, then retry sync. The device keeps receiving the last successful image during failures. Diagnostics retain the latest 200 records and show the latest 30; Oban job history is pruned after seven days.

The named `database` volume contains configurations, encrypted connections, event snapshots, images, device credentials and diagnostics. `docker compose down` preserves it; **`down -v` deletes all application data**. Back up `.env` securely and take a PostgreSQL dump:

```sh
docker compose exec -T db pg_dump -U trmnl -d trmnl -Fc > trmnl.dump
# Restore into a stopped app / compatible fresh database:
docker compose stop app
docker compose exec -T db pg_restore -U trmnl -d trmnl --clean --if-exists < trmnl.dump
docker compose up -d app
```

## Local development and verification

Tested toolchain: Elixir 1.20.3 / OTP 29 locally; deployment uses Elixir 1.18.4 / OTP 27.3.4. PostgreSQL 17, Node 22+, Playwright 1.56.1 and ImageMagick 6 or 7. Locked Hex/npm dependencies are included. Node is only needed for rebuilding the checked-in JS bundle and for the renderer/tests.

Start PostgreSQL locally on `127.0.0.1:55432` with user/password `postgres`/`postgres`. Development and ExUnit use separate `trmnl_dev` and `trmnl_test` databases.

```sh
mix deps.get
mix ecto.create
mix ecto.migrate
npm ci
npm run build
npm --prefix renderer ci
cd renderer && npx playwright install chromium && cd ..
# First terminal (use MAGICK_BIN=magick for ImageMagick 7):
RENDERER_SECRET=development-renderer RENDERER_HOST=127.0.0.1 node renderer/server.mjs
# Second terminal:
python3 scripts/start_dev.py
```

Open `http://localhost:4010`; development password: `development-password`. Production has no fallback credentials. Development port defaults to 4000; the example uses 4010 to avoid existing local services.

```sh
mix precommit                   # compile, remove unused locks, format and run tests
RENDERER_TEST=1 mix test          # also exercise running real renderer on port 3001
npm run test:browser             # disposable development DB; edits layout and pairs simulated MAC
```

Browser tests intentionally mutate the target deployment. Use them only against disposable validation data. For an isolated Compose test, generate a separate environment file, choose a free port and project name, then run:

```sh
docker compose --env-file .tmp/compose.env -p trmnl-validation up --build -d --wait
BASE_URL=http://localhost:4011 ADMIN_PASSWORD=YOUR_TEST_PASSWORD DEPLOYMENT_TEST=1 DOCKER_TEST_CONTEXT=default COMPOSE_TEST_ENV=.tmp/compose.env COMPOSE_TEST_PROJECT=trmnl-validation npm run test:browser
```

The deployment test stops/restarts **that project's** services, simulates renderer failure, retries through the dashboard, and verifies persisted draft/image/device credentials. `test/support/fixtures.ex` and Req.Test stubs provide deterministic Google account/event responses. The real-renderer test writes a dense week/agenda example to `artifacts/calendar-screen.png`; browser tests write `artifacts/dashboard.png` and `artifacts/browser-preview.png`.

## Repository map

- `lib/trmnl/`: persistence, layouts, Google synchronization, encryption, devices, publication, diagnostics and rendering.
- `lib/trmnl_web/`: LiveView editor, admin/OAuth controllers and device API.
- `config/`: development/test/production configuration; production secrets loaded at runtime.
- `priv/repo/migrations/`: application and Oban migrations.
- `renderer/`: internal authenticated Chromium/ImageMagick service and container.
- `assets/`, `priv/static/`: browser source, built bundle and generated onboarding images.
- `test/`: ExUnit, LiveView, adapter, contract, rendering and Playwright tests.
- `docs/VALIDATION.md`: observed acceptance results and remaining integration checks.

`AGENTS.md` is preserved as supplied. Real Google consent and the physical TRMNL/home-server integration cannot be inferred from fixture or simulated-device success.

The daily three-task module replaces Today + tomorrow. Existing entries and blocks retain their internal type key for compatibility; no content is deleted. Legacy days with more than three entries display the first three by creation order; remove or move excess entries before adding another. Completed tasks still count toward the daily limit.

The date/time block shows the Warsaw time at image generation with “±5 min”. Published clock screens refresh server-side every minute and devices poll every four minutes; outages can leave an older image. Other screens retain 15-minute device polling. Use `python3 scripts/package_release.py` from the source checkout to create the source deployment archive and checksum in `dist/`.
